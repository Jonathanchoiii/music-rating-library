# RecordShelf 版本变更记录

本文件只记录已经进入代码或打包产物的变化。产品规则与验收标准以
[`PRD.md`](../PRD.md) 为准，维护分工见 [`MAINTENANCE.md`](MAINTENANCE.md)。

## 0.1.22 — 2026-08-18

### 新功能

- 艺人详情的平台主页图标现在由已确认链接实时驱动：保存 Apple Music、Spotify 或 YouTube Music 艺人主页后，对应图标立即高亮并可跳转；未填写的平台保持禁用，链接编辑继续使用独立铅笔入口。
- 艺人索引新增艺人详情抽屉：沿用发行详情 `690px` 窄抽屉与关闭/返回习惯，桌面和移动端统一使用单列竖排；顶部只保留 Apple Music、Spotify、YouTube Music 艺人主页和 Apple 艺人素材四个紧凑工具图标。
- 艺人详情支持用户为当前艺人保存精确平台主页，并按需读取 Apple Music 艺人静图与动态视觉：目录同时请求 `editorialArtwork` 与 `editorialVideo`，静图优先方形身份图再横版 1400/1000 和 600px 兜底，动态视觉优先方形 1:1 再压缩为本机 H.264 MP4（先 1080×1080 / 30fps / crf 18；超 8 MB 先自动截短时长，再降档，直到 ≤8 MB）。体积超限不再失败回退静图，只有完全没有可播放视频时才保留高清艺人图；不触发全库扫描，也不抓取第三方 artwork-finder 页面。旧 WebP 仅在用户点击素材刷新后替换。
- 艺人详情展示本地确认的主显示名、别名、收录数量与平均分；顶部视觉先安全复用该艺人已有发行封面，避免未核验外部图片造成错人。
- “我的收录”支持 `全部 / LP / EP / Single / 未分类` 切换，按发行日期从新到旧排列；专辑可切换为紧凑列表或封面宫格，并按艺人记住选择；从艺人详情打开发行后，关闭发行详情会回到原艺人详情。
- 探索模式开关写入 Web 与 Mac 共用的本地增量；当前阶段不自动联网、不伪造待解锁作品，后续只能由用户手动刷新精确目录。
- 合作关系按 RecordShelf 本地共同署名精确统计，可继续进入对方艺人详情。
- 艺人介绍的手动更新入口已接入本机研究服务：优先使用已确认 MusicBrainz Artist MBID，否则只接受唯一的高置信精确姓名/别名结果；读取并缓存出生或成立日期、地点、国家/地区、艺人类型、流派、团体成员、来源和可用的 Wikipedia 公开简介。Codex 长文仍只走本机已登录 CLI；不可用、未登录、超时或失败时保留公开档案并作为部分成功展示，不自动换 Gemini/OpenAI。同名有歧义时保持空白并提示先绑定 MBID，普通打开与同步不会自动联网。
- 艺人公开简介补充 Wikidata sitelink 降级链：从已核验 MusicBrainz 身份读取 Wikidata 条目，优先中文 Wikipedia、再尝试英文 Wikipedia；任一介绍源不可用时仍保留已经确认的出生、地区、流派与团员等结构化事实。
- 艺人详情支持点击抽屉外左侧遮罩关闭，身份区移除“原始艺人署名”冗余眉题；顶栏去掉通用「艺人详情」标题。已核验艺人照片或动态素材撑满抽屉宽度并裁成 1:1；渐变模糊只占正方形下部底带（固定 36% 高、实心 94%），用更长缓入过渡到暖白，去掉发丝分隔。姓名、统计和平台图标叠在该下部渐变上，「我的收录」从 1:1 框下沿开始。头图渐变比例已固化进 CSS，不再提供「头图渐变」调节器。关闭按钮叠在照片上时反白，叠在纯色表面时恢复深色。封面拼贴回退仍内缩。资料更新状态、失败信息和结果会在当前页面即时显示并写入 Web/Mac 共用本地增量。
- 详情封面刷新按钮仅在桌面悬停或聚焦时以 30% 不透明度出现，相对原内缩再向右、向下各移 8px；动态封面上同样可用。本地 `/private-covers/` 缺失或无法解码时，网格和详情先显示已保存的远程 `coverRemoteUrl`，Mac 读封面时额外回退到本机 `.private/covers`。

### 修复与调整

- 艺人静图现在优先使用 Apple 方形身份图（`artwork` / `staticDetailSquare`），没有方形时才用横版 `subscriptionHero`。1:1 Hero 因此会显示与 YouTube Music 头像同一张官方照片，而不是把 4:1 横幅中心裁切；仍只读已确认 Apple Music 艺人目录，不抓 YouTube 头像或第三方图片。已缓存的横版图需用户再次点击素材刷新才会换成身份图。
- 艺人详情别名会丢掉 MusicBrainz 把 Shift-JIS 日文误读成 Windows-1252 的检索提示（例如 `‰F‘½“cƒqƒJƒ‹`）。能还原的会还原成正确假名后再去重，不再显示在身份叠字行。
- 艺人照片 Hero 的收录统计与别名不再跟随标题反白：姓名仍按标题带采样（深底白字），但落在实心暖白渐变上的「N 张已收录发行 · 平均 X」、别名和素材截短提示保持 `--muted-dark`，避免白字叠在奶油底上看不见。
- 修复点击艺人后详情抽屉打不开：介绍区现在从 `profile` 读取奖项、提名、影视关系、推荐聆听和来源，不再因未定义变量在选中后立刻崩溃。`/artists?artist=` 会把 `raw-doja+cat` 这类 `+` / `%20` 编码还原成与分组一致的空格 ID。
- 艺人主页流媒体链接现在会立即写入 Web/Mac 共用的 `artistProfiles` 增量。含空格的未映射 ID（如 `raw-doja cat`）、URL 编码变体和已映射身份读取同一份档案；空的 `{ profiles: {} }` 合并不再清掉已保存的 Apple Music / Spotify / YouTube Music 链接和本机封面/动态素材。重新打开艺人详情应还原上次保存的结果，而不是看起来像第一次拉取。
- Apple 艺人 `editorialVideo` 常把 `PreviewImage`/`nonvideo` 的 `mv.webp` 预览静图放在 `.video` 字段；只接受 `*.itunes.apple.com` 上的 HLS `.m3u8`，这种静图不再当作动态视频去压，也不再提示「动态视频地址无效」。有真正 m3u8 时仍优先方形再编码 MP4。含空格的未映射艺人 ID（如 `raw-doja cat`）会写成安全文件名后再压缩，不再被误报成「地址无效」；界面也不会把这份过期错误叠在已有本机 MP4 或合法 HLS 上。
- 发行详情关闭条在抽屉内滚动时保持置顶：`.release-drawer > .drawer-topbar` 使用与艺人详情相同的透明 sticky 覆盖（`top: 0`、高层级、56px 高并负底边距叠在封面上沿），右侧 44 × 44 关闭始终可点；不显示「发行详情」标题，也不套用窗口 32px 拖拽偏移。
- 「平台评分」芯片改为 `inline-flex` 内容宽度：列表 `flex-direction: row; flex-wrap: wrap`，卡片 `flex: 0 0 auto; width: max-content`。豆瓣与 Record Club 等两张能放入 630px 抽屉时同一行，只有下一张放不下才换行。
- 艺人公开档案的流派改为紧凑的低对比度浅灰标签：移除流派整行的大块灰底，只保留小字号、轻圆角的独立标签，并在桌面与移动端自然换行。
- 「平台评分」标题右侧刷新改用与「聆听指南」相同的 Phosphor `ArrowClockwise` 图标。
- 艺人公开档案的「团体成员」与「流派」并入成立/来自/地区/类型同一事实网格；成员姓名用 ` / ` 分隔，`original` / 原始 / 原始成员等冗余角色不再跟在姓名后。Codex 联网介绍失败或资料不足时，仍写入并展示本次或上一份 MusicBrainz 已核验事实（出生/成立、来自、地区、类型、成员、流派），不再把整块基础信息留空；失败提示可以保留。前端不再把所有 Codex 错误码都显示成「Codex 联网研究没有完成」：有公开事实时显示灰色说明并保留事实区，身份冲突与真正没有档案时才用红色错误。
- 艺人介绍公开事实网格（成立/来自/地区/类型/团体成员/流派标签）与章节标题、说明和正文共用同一左缘，去掉多余左缩进。
- 身份区右侧铅笔与 Apple 素材刷新统一为 `.icon-button`：相同 regular 描边、`var(--text)`、21px SVG，并右对齐。
- 艺人 Hero 动态素材改为 muted 循环 MP4，CSS `scale(1.2)` 铺满，底部渐变遮缝；体积超过 8 MB 时自动截短时长并保留 MP4，而不是改回静图。
- 应用与桌面包版本更新为 0.1.22。

### 数据与隐私

- 本版本不迁移、不重置也不合并私人音乐数据；继续使用
  `~/Library/Application Support/RecordShelf/shared-local-state.json` 作为 Web 与 Mac 的共享用户增量。
- 艺人主页链接、Apple 艺人静图/动态 MP4 与空增量保护都写在同一份共享 `artistProfiles` 增量里；没有新增凭证、私人目录或远端传输字段。
- 手机只读预览快照现在会带上艺人动态 MP4，仍不得进入 Git、DMG 或 GitHub。

### 验证

- 应用测试：284 项通过。
- Sites worker 测试：7 项通过。
- Web 构建和公开构建隐私检查通过。
- Electron 主进程、本机服务和后台 worker 语法检查通过；Git 冲突标记和空白错误检查通过。
- 本地 Apple Silicon DMG：`app/desktop-release/RecordShelf-0.1.22-arm64.dmg`。

### 已知限制

- 本地 DMG 使用 ad-hoc 签名，未使用 Apple Developer ID 公证，不适合作为公共安装包分发。
- 现有前端仍有较大的代码分块构建警告；不影响本次功能，但后续应单独做按路由/功能拆包，而不是与交互修复混改。

## 0.1.21 — 2026-08-16

### 修复与调整

- 发行详情顶栏去掉通用「发行详情」标题，只保留右侧关闭；对话框仍用发行标题作为可访问名称。
- 详情模块标题（专辑介绍、曲目列表、收听时间、聆听指南、平台评分）统一为 20px。
- 发行类型与平台/动态封面图标仍在同一工具行；只有窄宽度折行时，第二行左侧补与「发行类型」同款的「收听链接」，单行不出现该标题。
- 「专辑介绍」空状态说明改为「可手动添加或配置令牌自动拉取」；不改写 Apple 官方原文，也不加「我写的」标识。
- 为 macOS 客户端增加单实例锁：重复双击当前版本只激活已有窗口，不再启动第二个服务并误报 `4173` 被占用；真正由历史客户端占用端口时仍保留明确退出提示，避免新版加载旧 UI。
- 发行详情顶部新增克制的封面取色氛围：封面在本机缩小为 20 × 18、共 360 个等面积采样格，只以占比最大的单一 HSB 色簇生成轻渐变，不再混入第二颜色。为避免深色封面形成压迫的深底白字，主色按 `B新 = B旧 + (100 - B旧) × 0.7` 提高明度，保留原色相与饱和度，并固定使用浅色背景与黑字；渐变层整体降为 50% 不透明度，范围收敛至详情顶部约 195px，并在进入封面主体前淡回暖白。修复 NeoDB 等跨域远程封面无法取色、导致渐变透明度始终为 0 的问题：本机服务现在仅对固定可信 HTTPS 图片域名提供受 MIME 与 15 MB 上限保护的临时同源字节回退，不保存或上传封面、不写入唱片元数据，失败时仍静默保持原背景。
- 取消窄屏唱片架的纵向 Cover Flow 分支；桌面、窄窗口与手机现在统一使用五张一层的横向实体唱片架，并按容器同步收紧封面、间距、层高、编号和 hover 位移。
- 移除「专辑介绍」底部重复的「在 Apple Music 中打开」链接；Apple Music 跳转统一保留在详情头部的平台图标区。
- 恢复发行详情右侧 NeoDB、Apple Music、Spotify 图标的桌面右键链接编辑：组件自身处理右键事件，打开添加、修改或清除链接的站内菜单。
- 保持移动端长按链接图标进入同一编辑流程；平台链接继续写入 Web 4173 与 Mac 共用的用户增量，不只停留在当前页面。
- 收紧事件边界：不再用捕获阶段提前拦截目标组件，也不在 Electron 主进程全局禁用所有原生 `context-menu` 事件，避免链接编辑失效并保留其他界面的正常右键能力。
- 修复旧客户端仍占用 `4173` 时，新客户端静默复用旧版页面的问题：现在会明确提示先退出旧进程，不再让废纸篓或历史安装包伪装成当前版本。已在当前构建上实测右键后出现「修改链接 / 清除链接」。
- Mac Dock、应用窗口与 DMG 统一使用用户提供的 `record` 素材。移除启动后的 `app.dock.setIcon()` PNG 覆盖，改由 `.app` bundle 图标统一承接关闭与运行状态，修复未打开时圆角正常、打开后却变成方形的问题。
- 应用与桌面包版本更新为 0.1.21。
- 修复「更新专辑封面图」把仍可访问的旧 NeoDB 远程地址直接缓存后计为成功的问题：现在会先按已确认的 Apple Music / Spotify 精确链接重新解析；两者都返回时记为精确平台共识，覆盖过期 NeoDB OG。空白或客户端加载失败的旧地址不会靠 `coverRemoteUrl` 回退成成功。本地 `/private-covers/` 被覆盖后用 `coverMatchedAt` 刷新图片请求。
- 发行详情英雄封面在桌面悬停或键盘聚焦时，右下角出现 30% 不透明度的刷新按钮；点击只对当前这张发行 `force` 重解析精确链接封面，即使本地 `/private-covers/` 已存在也不空转。手机保持 44 × 44 热区。设置页批量「更新专辑封面图」仍先处理空缺、失败和远程封面。网格与唱片架不显示该控件，也不恢复独立平台链接行。

### 数据与隐私

- 平台链接修改仍通过现有共享增量写入；没有新增凭证、私人目录或远端传输字段。
