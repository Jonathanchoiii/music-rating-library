# RecordShelf「艺人详情页」Prompt PRD

> 状态：艺人详情、按需 Codex 联网研究、动态视觉与精确探索目录均已接入。探索目录只在用户主动刷新后读取。
>
> 日期：2026-08-16

## 1. 一句话定义

把当前“点击艺人名后触发一次搜索”的过渡行为，升级为以稳定 `artist_id` 为核心的艺人详情页：同时呈现用户在 RecordShelf 中已经听过的作品、经可靠来源核验的公开艺人档案，以及由用户主动触发的探索目录、艺人介绍和动态视觉。

这不是一个新的音乐社区，也不是无来源的百科页。页面首先回答三个问题：

1. 我在 RecordShelf 里听过这位艺人的什么？
2. 这位艺人是谁，哪些公开资料可以被可靠证明？
3. 如果我想继续探索，下一张作品或下一位相关艺人可以是谁？

## 2. 目标与非目标

### 2.1 目标

- 使用现有艺人身份、别名与 MusicBrainz MBID 体系，避免同名艺人串页或别名分裂。
- 音乐库载入、NeoDB 同步或手动添加唱片时，尚未映射的完整艺人署名自动生成稳定本地身份并进入艺人管理；同一规范化署名只建一次，MBID 仍须通过现有“精确名称/别名 + 共同 Release Group 标题”证据核验后写入。
- 用高清艺人图、主显示名、别名和少量可靠事实建立清晰的顶部身份区。
- 按 `LP / EP / Single` 展示 RecordShelf 已收录作品，并保留封面、原语言标题、发行日期和用户评分。
- 提供默认关闭的“探索模式”。用户主动刷新后按已确认 Apple Music Artist ID 读取 LP、EP、Single 与曲目；未听曲目灰显，并显示唯一歌曲口径的歌手完成度。
- 提供一次一位艺人的手动研究：生成约 700–1000 个中文字符、带来源的艺人介绍。
- 展示可证明的合作关系；团体艺人另外展示成员及其角色。
- Apple Music 艺人动态视觉只允许单人、单次、手动请求，并在本机压缩与缓存。
- Web 4173 与 Mac 客户端读取同一份艺人资料、探索状态和生成结果。

### 2.2 非目标

- 首版不做关注、粉丝、社区动态、排行榜或艺人新闻流。
- 不对单曲评分，不展开制作人、作词、作曲等逐曲 credits；这些属于下一阶段。
- 不用名字相似度自动合并艺人，不用国籍、照片或作品语言猜测身份。
- 不自动全库抓取艺人图片、简介、完整作品目录或动态视频。
- 不把“未听过”解释为“不喜欢”，也不把平台目录缺失解释为作品不存在。
- 不绕过登录、验证码、地区限制、robots、平台条款或未公开授权下载受保护媒体。

## 3. 核心产品原则

### 3.1 身份先于内容

艺人页必须绑定稳定 `artist_id`。只有艺人身份已经由用户确认，或存在足够的 MBID + 共同作品证据时，才允许写入外部资料。名字搜索结果只能作为候选，不能直接成为事实来源。

### 3.2 本地档案与外部目录分层

- **我的收录：**RecordShelf 内已经存在、已经听过或已经标记的发行，是第一层内容。
- **探索目录：**外部精确目录中存在、但本地没有有效评分记录的作品，是第二层内容。目录结果缓存于本机共享艺人资料，普通打开不联网。
- 两层不得混合计数；卡片必须明确“已听 / 在听 / 想听 / 待解锁”等状态。

### 3.3 证据不足就留空

生日、出生地、活动地区、团体成员、获奖、合作次数等字段均需要可追溯来源。出生地和“来自哪里”不是同一个字段；获奖和提名必须分开；团体成立地不能当作每位成员的出生地。

### 3.4 默认不联网，主动请求才消耗

普通打开、返回、滚动、切换 LP/EP/Single、NeoDB 同步和应用启动均只读取缓存。以下能力只能由用户主动触发：

- 更新公开艺人资料；
- 开启或刷新探索目录；
- 生成或更新艺人介绍；
- 请求 Apple Music 艺人动态视觉。

## 4. 信息架构与导航

### 4.1 推荐路由

- Phase A 沿用现有兼容路由 `/artists?artist={artist_id}`，避免破坏已保存的音乐库工作区、返回位置与发行详情回退链路。
- 后续可增加规范路由 `/artists/{artist_id}`；旧路由只负责解析到稳定身份并替换为主路由。存在歧义时进入身份选择，不默认取第一个同名艺人。
- 从发行详情点击单个艺人名，进入该艺人详情页；合作署名中的每位参与艺人分别可点。
- 返回音乐库时恢复原发行详情、滚动位置、筛选、排序、搜索、视图和已加载批次。

### 4.2 页面结构

1. 艺人 Hero
2. 公开档案
3. 我的收录
4. 探索模式作品
5. 艺人介绍
6. 合作关系
7. 团体成员（仅团体）
8. 来源与更新时间

艺人详情必须沿用发行详情的交互与容器：右侧抽屉宽度为 `min(100%, 690px)`，桌面与移动端均使用单列纵向信息流，不使用双栏、侧边资料栏或横向 Hero。移动端保持相同信息顺序，不新增独立的移动功能；卡片、标签和操作可折行，但不得横向溢出。

Phase A 的顶部使用与发行详情一致的紧凑工具图标，只提供 Apple Music、Spotify、YouTube Music 三个艺人主页入口、一个独立链接编辑入口和一个 Apple Music 艺人素材请求入口。保存精确主页链接后，对应平台图标立即高亮并可直接打开；缺少链接的平台图标保持低强调、禁用且不可点击，统一通过铅笔按钮进入编辑。不展示冗长的数据来源说明。

## 5. 页面模块规格

### 5.1 艺人 Hero

必须展示：

- 经精确艺人身份确认的高清横向或竖向艺人图，撑满详情抽屉宽度、裁成 1:1、`object-fit: cover; object-position: center` 不留黑边。渐变模糊只占正方形下部一条底带（固化 `--artist-hero-veil-height: 36%`，实心停在 `--artist-hero-fade-opaque: 94%`），上半照片保持可见；遮罩画在裁切框内，缓入过渡到底边完全不透明的暖白，不得露出未遮照片条或发丝分隔。艺人标题保持居左，整块身份区叠在该下部渐变上，不在照片下方另起一段。叠在照片上的姓名按标题带亮度自动选白字或黑字；别名、收录统计和素材提示始终用深色低强调字，因为它们落在实心暖白渐变上。关闭按钮与照片左右全出血不动。没有可靠图片或动态视觉时使用该艺人在 RecordShelf 中已收录发行的封面拼贴，不抓取搜索结果中的任意图片。不再提供「头图渐变」调节器。
- 主显示名。
- 别名：使用较小字号、低强调灰色，最多显示 3 个；更多别名进入展开区。
- 艺人类型：个人、团体、管弦乐团、合唱团或其他已核验类型。
- 顶部平台工具保持紧凑：已有精确艺人主页链接时图标高亮并直接跳转；缺少链接时图标低强调、禁用且不可点击，链接编辑由独立铅笔按钮负责；Apple 素材按钮只请求当前艺人。普通打开不联网，工具不得挤占艺人姓名和别名区域。

图片来源优先使用已经确认的艺人平台 ID。Spotify 图片只能依其平台政策原样展示和署名，不做下载、裁改或再分发；若不适合本机缓存，则保存远程来源和尺寸，不保存图片文件。

### 5.1.1 Phase A 当前实现边界

- 使用已确认的本地艺人身份、别名与发行关系打开艺人详情抽屉。
- 顶部视觉优先显示已保存在本机的 Apple 艺人动态 MP4（旧 WebP 在用户刷新前仍可读），其次使用已确认 Apple 艺人静图：目录查询同时读取 `editorialArtwork` 与 `editorialVideo`；静态图优先方形身份静图（`artwork` / `staticDetailSquare`）再横版 editorial hero，并保留 1400/1000 以及 600px 兜底。`editorialVideo` 的 `PreviewImage`/`nonvideo`/`mv.webp` 预览静图不能当视频；只编码 `*.itunes.apple.com` 的 HLS `.m3u8`。含空格的未映射艺人 ID 必须写成安全文件名后再压缩，不得把合法 HLS 误报成「地址无效」。已保存的 Apple Music / Spotify / YouTube Music 艺人主页与本机 `imageUrl`/`localMotionUrl` 必须写入共享 `artistProfiles` 增量并在重新打开时还原；URL 编码变体与映射身份读取同一份档案，普通打开不得因为链接丢失而重新拉取封面。动态视觉优先方形 1:1，没有方形再取 16:9 并在转换时中心裁成 1:1（禁止黑边）。艺人动态编码为本机 H.264 MP4（先 1080×1080 / 30fps / crf 18；超 8 MB 先自动截短时长，再降档，≤8 MB），用 muted 循环 `<video>` 并以 CSS `scale(1.2)` 铺满；二者都撑满抽屉宽度、裁成 1:1；渐变模糊只覆盖正方形下部底带并在底边完全盖住照片，固化 36% 高、94% 实心，艺人标题保持居左并叠在该渐变上。已有动态素材时可用与发行详情相同的 video-album 开关切回静图。叠在照片上的姓名按亮度自动反白；别名/统计保持深色低强调。「我的收录」紧接 1:1 框下方，头部与后续模块之间不加发丝分隔。没有可靠图片或动态视觉时使用该艺人在 RecordShelf 中已收录发行的封面拼贴（内缩圆角），不抓取搜索结果中的任意图片，也不抓取第三方 artwork-finder 页面。探索模式与艺人介绍的标题操作使用发行详情聆听指南同款 44 × 44 `ArrowClockwise` 按钮，不用 Sparkle 或「已开启」胶囊；探索按钮只切换开关，不刷新目录。
- Apple Music 艺人主页只接受用户在链接编辑器中粘贴的精确 HTTPS Artist URL；不提供设置页或编辑器内的专辑反查匹配。不得按姓名模糊搜索 Apple 艺人，也不得在保存链接后自动请求静图或动态视觉。
- 抽屉顶栏不显示「艺人详情」文字；右上角关闭按钮在照片区域上自动反白，滚到纯色表面后恢复深色描边按钮。
- “我的收录”支持 `全部 / LP / EP / Single / 未分类`，按发行日期从新到旧排列；同时提供列表与封面宫格，并按稳定艺人身份记住选择。
- 探索模式保存用户开关偏好和最近一次成功的公开目录；只有用户点击刷新才联网。目录必须锚定已确认、带 storefront 的 Apple Music Artist URL，不得按姓名搜索或猜测同名艺人。已听/已收录作品仍保留在「我的收录」，探索区只把它们作为本地匹配与完成度证据。
- 合作关系只依据 RecordShelf 本地共同署名统计，可直接跳转到对方艺人详情。
- 艺人介绍只在用户点击局部刷新按钮后启动一次本机 Codex CLI 联网研究。请求使用稳定 `artist_id`、已确认外部 ID、精确艺人主页和本地已确认作品作为身份锚点；普通打开、同步、返回、应用启动和后台任务都不得自动触发。
- 研究任务按“准备身份 → 联网检索 → 核验来源 → 撰写介绍 → 写入本地”显示安全进度，不暴露隐藏推理。证据充分时保存 700–1000 个简体中文字符的来源化介绍，并同时结构化保存出生/成立日期、地区、类型、流派、团体成员、获奖、提名/入围、影视作品关系、推荐聆听、关键事实来源和警告。
- 出生地或成立地统一翻译为简体中文并按“国家 + 地名”展示；只有国家时只显示国家。获奖与提名/入围必须分区，逐项注明年份、奖项、类别和对应作品；影视作品关系必须明确为获奖、提名、入围、演唱、创作、制作或仅被影片使用。资料不足时字段留空，`INSUFFICIENT_SOURCES` 不覆盖上一份成功结果。
- 点击抽屉外遮罩、右上角关闭或 Escape 都返回艺人索引；身份区不显示“原始艺人署名”解释性眉题。抽屉顶栏也不显示「艺人详情」。

### 5.2 公开档案

按已有数据有条件展示，不出现成排“暂无”：

- 本名或官方名称；
- 出生日期 / 成立日期；
- 出生地 / 成立地；
- 主要活动地区；
- 活跃年份；
- 流派；
- 官方网站；
- 厂牌（有精确证据时）；
- 简短官方简介（有授权或可安全转述时）。

每个字段在数据层保存 `value`、`source`、`sourceUrl`、`retrievedAt`、`confidence`。界面默认不反复显示“精确信源”，但来源面板必须可查看。

### 5.3 我的收录

- 默认只显示 RecordShelf 本地已有发行。
- 顶部分类为 `全部 / LP / EP / Single`；不确定类型进入“未分类”，不靠标题后缀猜测。
- 标题右侧提供列表与封面宫格两个视图按钮；列表显示紧凑行项目，宫格在桌面为三列、手机为两列，均不得横向溢出。
- 两种视图都显示封面、主标题、发行类型、发行日期与 RecordShelf 当前评分，点击后进入同一发行详情；切换类型不得重置视图。
- 视图偏好保存在对应 `artist_id` 的本地艺人资料增量中，Web 与 Mac 共用；再次打开同一艺人时恢复上次选择。只读预览可切换当前会话，但不得写回共享数据库。
- 同一 Release Group 的 Deluxe、Remaster、Live 等版本是否合并，继续沿用发行身份规则；不同精确外链不得因同名合并。
- 合作作品在每位参与艺人的页面中出现，但全局只保留一个发行实体。

### 5.4 探索模式

探索模式默认关闭。首次开启只展示本机缓存；标题右侧 `ArrowClockwise` 与空状态按钮提供明确的用户触发刷新。刷新只发送公开 Apple Music Artist URL，并按精确 Artist ID 读取分页 albums 关系及每张发行的 tracks；普通打开、NeoDB 同步、返回和启动均不得触发。

- 外部目录中有精确身份、但本地没有有效评分的曲目，以统一灰阶、较低对比度和锁定标识显示。
- 待解锁曲目所在发行仍显示封面、名称、日期，可展开曲目并跳转到精确 Apple Music 页面；不能伪造用户评分、评论或“已听”状态。
- 本地唱片存在整数 `rating10` 时视为已听；匹配唱片中的曲目点亮。同一录音出现在 Single、EP、Album 或其他版本时，优先按 ISRC 合并并联动点亮；ISRC 缺失时才使用规范曲名 + 艺人 + 时长桶回退。
- `想听 / 在听 / 搁置` 保留其真实状态和灰阶表现；只有有效评分才计入本期完成度。
- 探索目录按 `LP / EP / Single` 筛选；不把名称搜索、推荐列表或相似艺人结果混入目录。
- 探索目录默认折叠同类型、同完整发行日期且基础标题相同的版本。基础标题只剥离末尾明确的版本限定词（如括号或破折号后的 Remix、Mix、Edit、Version、Remaster、Deluxe、Expanded、Anniversary、Bonus、Instrumental、Acoustic、Live、Sped Up、Slowed、Rework、Reprise），因此同日的 `Streets (Disclosure Remix)` 与 `Streets (Silhouette Remix)` 合为一行；不得仅凭同一天发行就合并基础标题不同的作品，也不得把 `Chapter One / Chapter Two` 等普通副标题当版本词剥离。
- 本地匹配优先使用确认的 Apple Music Album ID；仅在 Artist ID 已精确锚定、标题唯一、发行类型兼容且必要时年份可消歧时，允许标题回退。

歌手完成度 = 已听唯一录音数 ÷ 目录唯一录音数。页面显示百分比、已听/总歌曲数、已评分本地唱片数、匹配本地记录数与上次更新时间。普通打开只读取缓存；刷新失败保留上次成功目录。

### 5.5 艺人介绍

- 模块名建议为“艺人介绍”。
- 没有内容时只显示标题与右上角刷新图标，不展示阶段 A、空卡或编造摘要。
- 点击刷新后展示安全进度：准备身份、检索资料、核验来源、撰写介绍、写入本地；不展示模型隐藏推理。
- 首次成功后长期读取本地缓存；只有用户再次点击刷新才重新联网。
- 目标 700–1000 个中文字符。资料稀少时允许更短，不得为凑字数编造。
- 不使用用户评分、评论、听过时间或私人艺人映射来生成文章。
- 更新失败保留上一成功版本；“接口失败”和“可靠资料不足”必须是不同状态。Codex 未完成时仍展示已核验的出生/成立、地区、类型、流派和团体成员，不得把公开事实区清空。无 Codex 时回退 MusicBrainz + Wikipedia，不自动换 Gemini/OpenAI；有足够公开事实时记为部分成功，并用非阻断提示说明长文未完成。本机 Codex 必须带 `--ignore-user-config`，避免继承编程用 `config.toml` 模型（ChatGPT 登录可能已拒绝该模型）；失败分类读取 CLI JSONL。
- 同一次成功研究同时返回正文与结构化事实；不得先用百科短摘要伪装成完整文章，也不得将不同艺人、团体与成员的事实拼接。

### 5.6 合作关系

首版分成两种证据，避免一个模糊的“合作次数”：

- **库内合作：**依据 RecordShelf 中精确的共同发行 credit 计算，显示“共同收录 N 张”。
- **公开合作：**只有在 MusicBrainz 关系、精确作品 credits 或可靠官方资料明确支持时展示；不把“相似艺人”“同厂牌”“同歌单”算作合作。

每个合作项展示：

- 经确认的头像；没有可靠头像时使用中性身份图标；
- 主显示名与主要别名；
- 库内共同发行数量；
- 最多 3 张共同作品缩略图；
- 点击后进入对应稳定艺人详情。

合作次数按规范发行去重。同一作品的多个地区版本、Deluxe 与普通版是否视作一次，沿用当前 Release Group 规则并在数据层保留原始 credit。

### 5.7 团体成员

只对已核验为团体的艺人展示。每位成员可包含：

- 姓名与稳定 Artist ID；
- 角色 / 乐器；
- 加入与离开时间；
- 当前 / 前成员状态；
- 证据来源。

成员关系不完整时只展示可证明部分；不得根据舞台照片、维基分类或同名猜测成员。点击成员进入其艺人详情。

### 5.8 Apple Music 艺人动态视觉

- 这是实验性、本机视觉增强，不属于公开 Apple Music API 已承诺的目录字段。
- 只有存在已确认 Apple Music Artist ID 时显示动态视觉操作。
- 普通打开不检测、不下载。用户单次点击后才读取当前艺人页可公开访问的媒体证据。
- 只接受 Apple 固定 HTTPS 媒体域名和明确视频 MIME/HLS；不绕过登录、DRM、地区限制或验证码。
- 成功后在本机转换为循环 H.264 MP4（无音轨、优先约 8 秒、上限 8 MB；优先 1080×1080 / 30fps / crf 18）。超过 8 MB 时先自动截短时长，再降 fps/分辨率/crf，直到文件 ≤ 8 MB 后仍保留该 MP4，不得因体积失败回退静图。只有 HLS 缺失、网络失败或 FFmpeg 无法产出可播放文件时才回退静态艺人图。专辑动态封面仍是动画 WebP。艺人 Hero 用中心 1:1 裁切并在 CSS 里 `scale(1.2)`。
- 原始媒体、转码文件和运行时不进入 Git、JSON 导出、公开构建或 DMG；共享状态只保存本机私有路径、来源、尺寸、状态和检查时间。
- 失败时保留上次成功的动态 MP4 或静态艺人图，不清除原图；截短成功与真正失败使用不同状态文案。“未检查 / 无资源 / 已截短 / 请求失败 / 已缓存”是不同状态。
- 遵循 `prefers-reduced-motion`，并提供明确的开关。

## 6. 来源策略

### 6.1 来源优先级

1. 官方艺人网站、官方采访、奖项官网、厂牌公告。
2. 已确认的 Apple Music、Spotify、YouTube Music 艺人实体。
3. MusicBrainz / Wikidata 等结构化目录；只有精确 ID 或充分消歧后可写入。
4. 权威媒体专访与资料页。
5. 其他社区内容只用于描述公众回响，不用于生日、成员、获奖等硬事实。

### 6.2 平台适用字段

- **MusicBrainz：**稳定身份、别名、艺人类型、起止日期、地区、Release Group、关系和成员候选。
- **Apple Music：**精确艺人 ID、官方目录作品、流派、精选关系与平台艺人页入口。
- **Spotify：**精确艺人 ID、公开艺人名、图片、平台流派与入口；遵守其视觉内容不可下载和需署名等政策。
- **YouTube / YouTube Music：**仅使用精确官方频道时的标题、简介、缩略图和频道入口；搜索到的同名频道不能自动关联。
- **奖项官网：**获奖 / 提名届次、类别、作品与年份。

### 6.3 冲突规则

- 生日、成立日期等结构化字段冲突时不自动择一；保留候选与来源，界面显示“待核对”。
- 流派允许多值并保存来源，不把平台营销标签当作唯一事实。
- 官方资料可覆盖低可信聚合站，但不得覆盖用户确认的身份映射。
- 外部目录更新不能删除本地发行、评分、评论、收听历史或别名决策。

## 9. 状态与失败体验

### 9.1 资料状态

- `EMPTY`：尚未请求；不显示空字段堆叠。
- `READY`：展示缓存与更新时间。若 Codex 长文未完成但已有 MusicBrainz / Wikipedia 公开档案，仍为 `READY`，并用非阻断说明提示长文未完成；不自动换 Gemini/OpenAI。
- `STALE`：公开身份或精确外链变化；继续展示旧内容，提示可手动更新。
- `IDENTITY_CONFLICT`：外部身份冲突；引导去“设置 → 艺人管理”核对。
- `INSUFFICIENT_SOURCES`：已完成检索但证据不足；不写正文。
- `FAILED`：网络、配额、权限、同名无法消歧，或 Codex 与 MusicBrainz 都不可用；保留旧内容并给可重试原因。

### 9.2 任务状态

艺人介绍与动态视觉任务均以 `artistId` 去重：同一艺人同类任务同时只允许一个。页面关闭后任务可以继续，重新打开恢复进度；成功后当前页面轻量刷新，不能要求用户重启客户端。

## 10. 响应式与可访问性

- 桌面端 Hero 使用图片与身份信息双栏；窄屏改为上图下文，不压缩主名和操作热区。
- 作品区在桌面使用自适应网格，在移动端至少双列；锁定态不能只靠颜色区分，必须有文字或图标。
- 所有平台、刷新、探索和动态视觉图标提供可访问名称、键盘焦点和 44 × 44 最小热区。
- 低强调别名仍需满足可读对比度，不以极低透明度牺牲可访问性。
- 动画遵循系统“减少动态效果”。

## 11. 验收标准

### AC-A01 稳定身份导航

**Given** 一个艺人身份有主名、多个别名和稳定 Artist ID
**When** 用户从任一归属于该身份的发行点击艺人名
**Then** 进入同一个艺人详情页，展示该身份下全部本地作品；评论里偶然出现的同名不会影响结果。

### AC-A02 同名安全

**Given** 两位艺人显示名相同但 MBID 或共同作品不同
**When** 用户打开其中一位艺人详情
**Then** 页面只读取该稳定身份的资料和发行；无法消歧的外部结果不写入。

### AC-A03 我的收录分类

**Given** 当前艺人的本地发行包含 LP、EP、Single 和未分类
**When** 用户切换分类
**Then** 卡片只按人工确认或精确信源类型切换，显示封面、标题、日期和评分，不靠标题猜类型。

**Given** 用户位于某一艺人的“我的收录”
**When** 在列表与封面宫格间切换并重新打开该艺人
**Then** 两种视图展示同一筛选后的发行集合，专辑详情入口一致，并恢复该艺人上次选择。

### AC-A04 探索模式

**Given** 探索模式关闭
**When** 用户普通打开艺人页
**Then** 不联网，也不显示未听目录。
**When** 用户主动开启探索模式
**Then** 写入本地 `explorationEnabled` 偏好并展示已有缓存或明确的手动刷新入口；开启本身不联网。
**When** 用户在已有确认 Apple Music Artist URL 的情况下主动刷新
**Then** 只发送公开 Artist URL，按精确 Artist ID 读取 LP、EP、Single 与曲目；本地有效评分唱片对应的曲目点亮，其他曲目灰显，按 ISRC 优先去重后显示歌手完成度。刷新失败保留上次成功目录，评分、评论和收听日期不得离开客户端。

### AC-A05 艺人介绍

**Given** 艺人介绍为空
**When** 用户点击生成
**Then** 只发送公开身份锚点，显示安全进度；Codex 联网检索并交叉核验后，一次性保存可核验的出生/成立日期、中文地区、艺人类型、流派、团体成员、获奖、提名/入围、影视关系、推荐聆听、来源与 700–1000 字左右的介绍。失败、同名歧义或资料不足时不编造，也不覆盖旧版本；已核验的公开事实仍应保留并展示。无 Codex 时回退 MusicBrainz+Wikipedia，不自动换 Gemini/OpenAI。

### AC-A06 合作与成员

**Given** 本地存在精确共同发行，或 MusicBrainz / 官方 credits 存在可核验关系
**When** 页面展示合作关系或团体成员
**Then** 合作次数按规范发行去重，成员有角色和来源；相似艺人、同厂牌或同歌单不被算作合作。

### AC-A07 动态视觉按需

**Given** 艺人有已确认 Apple Music Artist ID
**When** 用户未点击动态视觉
**Then** 不产生检测或下载请求。
**When** 用户主动请求且存在可合法读取的媒体
**Then** 本机压缩、缓存并可关闭；失败时继续显示静态图，不影响艺人页其他内容。

### AC-A08 Web / Mac 共用

**Given** 用户在 Web 4173 更新了艺人资料、探索状态或介绍
**When** Mac 客户端打开同一 Artist ID
**Then** 读取同一份最新本机数据，不依赖另一个端口或独立 localStorage。

## 12. 建议分阶段实施

### Phase A：身份与本地艺人页

- 稳定 Artist ID 路由。
- Hero、别名、外链、公开档案容器。
- 本地发行按 LP / EP / Single 展示。
- 返回音乐库状态恢复。

### Phase B：按需公开资料与艺人介绍

- 已接入：本机 Codex CLI 单艺人手动联网研究、精确身份锚点、来源缓存、安全进度、700–1000 字介绍、结构化公开档案、团体成员、获奖、提名/入围、影视关系与推荐聆听，以及 Web/Mac 共享增量。Codex 不可用时回退 MusicBrainz 结构化事实与 Wikipedia 摘录（仅在尚无介绍时写入摘录），不自动改走 Gemini/OpenAI。
- 后续只优化信源覆盖与展示密度；不得改成后台批量研究或同步时自动研究。

### Phase C：探索与动态视觉

- 探索模式的外部精确目录、未听作品去重和点亮规则仍待交付；当前只保存开关并显示诚实空状态。
- 公开合作关系补充。
- 单艺人 Apple Music 动态视觉实验能力已按需接入。

## 13. 等待 Owner 确认的默认决策

本草案采用以下建议默认值；确认后才进入开发：

1. 艺人详情使用稳定 `/artists/{artist_id}`，旧 query 路由兼容跳转。
2. 探索模式默认关闭；只有“听过”、Listening Entry 或有效评分会完全点亮，想听 / 在听 / 搁置仍保留灰阶状态。
3. 探索主目录首版只收 LP、EP、Single，不把 Compilation、Live、Remix、Appears On 混入。
4. 合作模块首先显示可完全验证的“库内共同发行数”；公开合作只在有 credits 证据时补充，不展示不可证明的总次数。
5. 艺人介绍只由用户手动生成或更新；普通同步只更新公开身份快照，不自动消耗 Codex / API 额度。
6. 艺人动态视觉只支持单艺人手动请求；体积超 8 MB 时截短后仍保留 MP4，只有无法得到可播放视频时才回退静态图，不做全库扫描。
7. Phase A 通过后再开发 Phase B / C，避免一次上线身份、研究、目录和视频四类高风险能力。
